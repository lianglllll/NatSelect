# NatSelect 引擎问题修复计划

## 修复方案（分组实施）

### A. Core 层：Actor 调度与故障隔离（对标 skynet）

**A1. 重写 `NatSelect/Core/Actor.cs` 为 Kick/DrainAsync 状态机**
- 用 `SemaphoreSlim _gate` 串行化消息处理，`Kick()`（fire-and-forget）替代 worker 内联 await
- `DrainAsync`：一次最多处理 10 条（切片让出），邮箱读空后 `ClearScheduled()` + 双重检查闭合丢失唤醒窗口；有剩余消息则重新入队调度器尾部
- `HandleError` 改为返回 `bool`：`BusinessException`/`OperationCanceledException` 记日志继续；其他严重错误记 Error 并返回 true，错误路径直接调用 `DisposeAsync()` 完成终止（不再依赖永不被消费的 `SystemStopMessage`）
- 公开 `MailboxSize` 属性供诊断用

**A2. 重写 `NatSelect/Core/ActorScheduler.cs`**
- Worker 循环只从就绪队列 pop Actor 并 `actor.Kick()`（fire-and-forget），不 await 消息处理，恢复多 worker 并行能力，消除慢 Actor 占死 worker 与互相等待死锁
- `volatile bool _isStopping` 保证停止及时可见

**A3. 重写 `NatSelect/Core/ActorTimer.cs` 为邮箱投递模型**
- 到期时通过 `ActorContext.DispatchTimerTick` 向 Actor 邮箱投递 `TimerTickMessage`（在 `IAMessage.cs` 中新增），回调与消息处理串行执行，杜绝 `_messageCount` 之类的并发访问

**A4. 修改 `NatSelect/Core/ActorContext.cs` / `IActorSystem.cs`**
- `ActorContext` 新增 `AttachMailboxWriter`、`DispatchTimerTick`、`NotifyTerminated`（内部方法）
- `IActorSystem` 新增 `NotifyActorTerminated(ActorRef)`；`SpawnChild` 重名冲突抛 `BusinessException`（业务错误不导致父 Actor 崩溃）

**A5. 修改 `NatSelect/Core/LocalActorSystem.cs` 统一终止路径**
- `NotifyActorTerminated`：从注册表移除 + 通知 watchers（任何终止路径——错误、StopActor、正常退出——都走这里）
- `SendAsync` 目标不存在时静默丢弃（skynet 语义），不再触发误报的 watcher 通知
- `DisposeAsync` 改为轮询 `_actors` 清空（100ms 间隔、5s 截止），避免固定 3 秒延迟
- 诊断信息中 `MailboxSize` 改为真实值 `actor.MailboxSize`

**A6. 修改 `NatSelect/Core/NatSelectEngine.cs` 稳定 NodeId**
- `GenerateNodeId` 改用 SHA256（`Encoding.UTF8.GetBytes(_configPath)` 哈希取前 8 字节），保证同一配置跨进程重启 NodeId 一致

### B. Network 层：帧格式与消息路由

**B1. 修复 `NatSelect/Network/TcpConnection.cs`**
- 删除 `PrependLengthHeader`（双重长度头根因；`IMessageParse2ByteArray` 输出已含 4 字节长度头）
- 发送队列改 `Channel.CreateBounded<byte[]>(256, DropOldest)`，慢客户端丢弃最旧消息防内存膨胀
- `ConnectionId` 改 `Interlocked.Increment` 递增 ID，避免 socket handle 复用撞号
- `Close()` 用 `Interlocked.CompareExchange` 原子幂等；新增 `LastActiveTicks` 属性（`Interlocked.Read`）供空闲扫描

**B2. 加固 `NatSelect/Network/ProtoHelper.cs`**
- `ByteArrayParse2IMessage` 返回 `IMessage?`：数据 <2 字节、未知协议号、无 Descriptor 时记日志返回 null，不抛 NRE 不断连
- `AutoRegisterAll` 拒绝 `id > ushort.MaxValue`（帧内协议号仅 2 字节）
- `Seq2Type` 返回 `Type?`、`IMessageParse2ByteArray` 返回 `byte[]?`

**B3. 打通 `NatSelect/Network/NetworkService.cs` 消息路由**
- 新增 `public Func<long, IMessage, ValueTask>? OnClientMessage`，`HandleMessageSafeAsync` 统一入口：`NatSelectEnvelope` → 信封处理（`RegisterRemoteNode` 连接提升 + `HandleIncomingEnvelopeAsync`）；其他消息 → `OnClientMessage` 回调（未注册则丢弃并警告）
- 节点消息入口复用 `OnClientSocketAccepted` 同一套连接管理，收到合法信封即提升为节点连接
- 新增 `ScanIdleConnections` 定时器（30s 扫描 / 300s 超时），基于 `LastActiveTicks` 清理僵尸连接

### C. 清理与规范

**C1. 删除 Auth 业务模块（回滚回归项）**
- 删除 `NatSelect/Auth/AuthActor.cs`、`AuthMessages.cs`、`NatSelectDemo/Demo/AuthDemoActor.cs`
- `ProgramDemo.cs` 移除 `using NatSelect.Auth` 与 `RunAuthDemoAsync` 调用及方法（上次已确认"直接删除"）

**C2. 修正 `EchoActor.cs` 命名空间** 为 `NatSelectDemo.Demo`（匹配目录结构规范）
